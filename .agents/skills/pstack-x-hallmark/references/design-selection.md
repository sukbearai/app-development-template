# Choose references by the page's job

Keep the existing shell and visual system for ordinary administration changes. Read this selector when building a new page, changing a page's structure, or proposing alternatives during an audit. Reference selection is not permission to expand the task.

Separate visual treatment from content structure. A theme guides type, color, borders, and emphasis. A page structure organizes the information. Choose either or both when useful; do not force every task into a theme plus structure combination.

| Content or task                                                        | Reference to load                               | Use it for                                                                     |
| ---------------------------------------------------------------------- | ----------------------------------------------- | ------------------------------------------------------------------------------ |
| Technical product, API, SDK, or documentation page                     | [Cobalt](cobalt.md)                             | Clear technical hierarchy and code-centered explanations.                      |
| Metrics, filters, comparable records, or settings                      | [Grid](grid.md)                                 | Alignment, numeric typography, and consistent grouping inside the existing UI. |
| Product introduction or guided feature tour with real captures         | [Workbench](workbench.md)                       | Screenshots and concise task-oriented explanations.                            |
| Initialization, upload processing, or recovery with real ordered steps | [Narrative Workflow](narrative-workflow.md)     | Prerequisites, stages, outcomes, and recovery points.                          |
| Component documentation or interactive examples                        | [Component Playground](component-playground.md) | Existing Storybook previews, states, and usage examples.                       |

Other content may need only a semantic table, a link index, a question-and-answer list, or ordinary prose. Use the simpler structure when these references do not fit. For screenshots that explain a technical product, Cobalt and Workbench can be combined. For administration tables, Grid can improve alignment without selecting a new theme.

During an audit, explain which observed problem a proposed alternative would solve. Repeated cards, a familiar font, or a conventional layout are not defects by themselves. During implementation, briefly state the chosen structure and its content-based reason, then follow the authorized task without a new approval ritual.

Marketing and showcase briefs can explore a distinct visual direction when requested. Keep that direction local to the page, use real content and authorized assets, and preserve the shared administration system. Do not rotate themes based on prior runs or create historical stamps.
