# Cobalt for technical pages

Use for a technical product introduction, API example, SDK guide, or documentation home. The useful choices are precise hierarchy, restrained accents, thin separators, and real code as explanatory content.

- Lead with a concrete task or result. Place a short explanation beside a real request, response, command, or product capture when it helps the reader understand the product.
- Keep code selectable and use a monospace role for code and numeric output. Retain the existing body and heading fonts unless the brief asks for a new visual direction.
- Use the existing primary color for actions and selection. The Cobalt reference does not require changing pstack-x's primary color to blue. Keep success and error colors semantic.
- Use thin borders and consistent spacing to distinguish examples and sections. Add a contrasting code surface only if the actual syntax colors and text remain legible.
- Show the code's context and outcome. Keep illustrative fixtures labeled; do not present invented latency, test output, or API responses as measured results.
- Add a copy action or search affordance only when it works and serves the page. Reuse existing controls and keyboard behavior. A command palette is not a required dependency of this reference.
- Keep content visible without reveal animation. If motion helps, respect reduced-motion settings and preserve immediate keyboard focus indicators.

For an explicitly requested new marketing theme, a cool light background, restrained blue accent, and distinct code typography are possible directions. Keep them local to that page and verify contrast. Do not import upstream fonts, fake terminal chrome, forced uppercase labels, root clipping, or animation scripts merely to reproduce the theme.
