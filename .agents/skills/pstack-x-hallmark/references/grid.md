# Grid for data and settings

Use inside the existing administration shell when metrics, filters, records, or settings need clearer alignment. Borrow Grid's consistent alignment and typography without adopting its poster treatment.

- Align section headings, filter labels, controls, and table boundaries to common columns. Keep related labels and values together.
- Use tabular numerals for comparable values. Align numbers consistently and show units, time ranges, and status in predictable locations.
- Use a semantic table when users compare the same fields across records. Keep row and column relationships intact on narrow screens, using a local scroll region when necessary.
- For settings, group controls by the task they affect. Prefer consistent rows over arbitrary card-size variation. Use borders or spacing to explain grouping rather than outlining every element.
- Let the content determine column count. A fixed twelve-column display or a visible background grid is not required.
- Keep density appropriate to the task: compact rows for scanning, sufficient space around labels and interactive controls. Verify long names, empty values, translated labels, and keyboard focus.

Retain current radii, surfaces, fonts, and status colors. Do not add giant decorative numerals, geometric artwork, enforced lowercase headings, or a zero-card rule to administrative pages. A one-color identity rule must not remove meaningful warning or error distinctions.
