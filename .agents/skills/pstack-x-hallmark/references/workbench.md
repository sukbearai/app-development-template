# Workbench for a product tour

Use when a product introduction, feature page, or guide can explain the product through real screenshots. A product with no relevant interface or capture is better served by another structure.

Organize the page around the user's tasks. Give each task a concise heading, a real capture, and a caption explaining the action or result. Show enough surrounding UI to orient the reader, then emphasize only the relevant control or outcome. Use text beside the capture on wide screens and stack it on narrow ones.

Keep screenshots readable at their displayed size. Crop deliberately, provide meaningful text alternatives, and explain essential steps in text so the image is not the only source. Never include real credentials, private user data, or confidential content in a capture.

Place links to the demonstrated feature or guide where the reader has enough context to use them. Avoid a sticky call-to-action bar if it obscures content or focus. Screenshots should not masquerade as working controls. Use a real interactive demo only when the requested scope includes one.

Prefer real captures with a simple border. Do not add fake browser or device frames. If captures are unavailable, request the needed material or describe the proposed layout without claiming completed visual evidence. Do not invent screenshots, testimonials, usage counts, or benchmark results.

Adapted from [Hallmark Workbench](https://github.com/Nutlope/hallmark/blob/13ac0ec7e148655948100b6396439e481361d690/skills/hallmark/references/macrostructures/05-workbench.md). Fake frames, mandatory sticky actions, and reveal animation are not required.
