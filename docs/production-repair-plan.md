# 生产评估问题修复

状态为修复及本地完整验证完成，交付入口为 [修复结果](production-repair-results.md)。

基线为 `19f0e39`。本轮修改与验证仅在本地源码及新建隔离测试环境进行，不操作现有业务数据库。

## 阶段

1. 读取 poteto-mode 原则，固定基线。已完成。
2. Frame。将生产评估问题转换为失败回归和可检查的完成条件。
3. Design。沿用已确定的包边界，对上传状态、密码轮换和保留策略补充具体所有权；按真实故障风险安排实现顺序。
4. Run。身份、worker、数据库/上传、运维在独立 worktree 实现，父线程负责 UI、浏览器和合并验证。
5. Audit。记录修复前后证据及独立审查结论。
6. Verify。逐项回归后执行完整本地检查和容器验证，明确未验证的主机断电、外部业务与生产部署边界。

## 验收清单

| 问题             | 完成条件                                                                      |
| ---------------- | ----------------------------------------------------------------------------- |
| 管理表单原生 GET | 无 JS/延迟脚本时不能提交账号密码到 URL，正常创建不受影响                      |
| 心跳并发         | 并发写入不丢文件、不抛 ENOENT，停止后不被旧 running 写覆盖                    |
| 密码格式         | 登录、创建与初始化使用一致字符语义，首尾空格不被静默改变                      |
| 限流挤出         | 未到期的限制不因大量新 key 失效，存在整体尝试上限                             |
| 后台配置         | 真实运行入口使用配置的重试次数和 TTL                                          |
| 数据库漂移       | 拒绝拥有表上的不兼容额外列和约束，历史迁移不变                                |
| 上传身份锁       | 慢对象写入不阻塞登录/注销，提交前撤权仍拒绝且可安全补偿                       |
| 文件持久性       | 文件 sync、rename、目录 sync 顺序明确并实测，不宣称已做断电试验               |
| 存储协调         | 旧存储位置超过一页时仍能处理当前位置的孤儿；已提交引用受保护                  |
| 健康查询         | 数据库返回聚合与有界诊断，不加载全部历史记录                                  |
| 密码轮换         | 本人改密、管理员重置和显式运维恢复都审计并撤销旧会话                          |
| 历史保留         | 有界、显式执行的清理策略，保留幂等完成凭据，故障可重跑                        |
| 恢复流程         | 数据库与引用对象清单/校验一致，缺文件或损坏拒绝恢复，隔离恢复可登录与读取对象 |

风险最高的设计是上传的外部 I/O 与提交/清理协调。先验证状态所有权和故障窗口，再接线运维入口。四个工作区互不共享写目标，最终由父线程合并。
