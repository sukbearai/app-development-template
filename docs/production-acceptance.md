# 验收生产部署

在目标环境启用流量前完成以下验收。仓库内测试使用独立资源，不能替代目标环境的配置、容量和恢复证据。

## 核对配置与运行身份

1. 按 [生产部署配置](production-deployment.md) 准备实际配置，运行 `pnpm production:check`。命令必须成功退出。保留配置版本和结果，不保存口令或令牌。
2. 记录源代码提交、镜像摘要、数据库迁移版本、每个服务的副本数和资源限制。
3. 从实际公网入口验证 HTTPS、Cookie 的 Secure 属性及来源限制。验证入口按来源限流，确认一个调用方不能耗尽所有人的登录额度。
4. 多 Web 副本使用 Redis 限流和共享持久存储。上传文件后切换实例，验证元数据和文件字节仍可访问。共享目录声明不证明实际挂载相同。
5. 使编排器的停止宽限时间长于 Web 的停止期限。在有请求执行时停止一个实例，确认已接受的操作完成且新请求转移到健康实例。
6. Worker 使用独立的 `WORKER_SHUTDOWN_TIMEOUT_MS` 和更长的停止宽限时间。分别在初始化和在途事务阶段重复发送停止信号，核对正常收尾退出 0、超时退出 1，以及重启后的租约恢复和回执去重。初始化未完成的 starting 心跳不能被当作健康。

## 记录容量目标

上线负责人填写并发用户数、请求组合、最大上传大小、持续时间、允许的错误率及 P95 延迟目标。记录数据库和 Web 的 CPU、内存与连接限制。

按 [容量测试](capacity.md) 运行仓库基准。针对目标部署另行执行经授权的测试，并使用同一负载定义比较结果。检查身份写入等待、连接池等待、上传拒绝率和内存峰值。按实测结果调整每进程上传并发限制。

本机基准的默认参数不是生产容量承诺。既有身份事务锁保持不变；先测量等待时间，再决定是否调整权限变更与业务写入的协调方式。

## 验证告警接收

按 [运行指标与监控](monitoring.md) 接入每个实例的指标，并配置告警接收方。在获得故障演练授权的隔离环境中分别验证以下条件。

| 演练 | 需要看到的证据 |
| --- | --- |
| 停止发布，继续创建业务事件 | outbox 等待时间增加，告警按策略触发并送达 |
| 停止消费，继续发布 | Kafka consumer lag 或业务完成期限超限告警送达 |
| 使数据库不可用 | 指标报告数据库不可用，监控不能把它视为零积压 |
| 使上传持续达到并发上限 | 请求及时收到上传繁忙响应，恢复后名额可继续使用 |
| 产生需要人工核查的隔离记录或 blocked 上传 | 对应告警送达，运维能够定位到受保护的诊断界面 |

指标检查命令不会发送通知。HTTP 成功、检查命令退出和通知送达分别记录。单次观测只表示当时条件成立，持续时间与通知去重由接入的监控系统执行。

## 演练恢复与切换

1. 明确允许的数据丢失时间 RPO 和服务恢复时间 RTO，配置备份频率、备份保留期和 Kafka 消息保留期。
2. 按 [恢复流程](recovery.md) 创建备份并恢复到全新数据库和独立存储。保留备份校验值、开始和结束时间。
3. 检查用户权限、文件内容、任务回执及外部业务结果。恢复后的会话凭据需要明确的失效策略，不能自动视为仍获授权。
4. Kafka 恢复必须满足现有历史与分区限制。恢复后的 transport 只支持一个消费者，实际重放速度应满足 RTO。
5. 切换前隔离旧部署的写入和消费者。验证新部署继续工作，记录回退条件，防止两套实例同时处理业务。

测试只证明当次恢复。实际外部接收方必须按稳定身份实现幂等；默认示例 Worker 的成功不能证明业务副作用正确。

## 留存验收记录

记录每项结果、时间、执行人、证据位置和未完成事项。只有实际观察到的路径标记通过。配置预检、仓库测试、隔离压测、目标环境演练和流量切换保持独立结果。
