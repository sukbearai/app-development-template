# 应用模板架构

Web 接收请求，先解析身份、校验来源和权限，再调用服务器用例。服务器用例通过 database 包完成一次业务写入。业务行、审计和 outbox 在同一 PostgreSQL 事务中提交。HTTP 结果在运行边界按 contracts 登记的 schema 验证，未知错误返回脱敏 500。

浏览器只依赖 contracts 与 React 组件。database 不依赖 server，server 不依赖 Web。连接池归应用进程所有；worker 退出时停止认领并关闭连接。避免在请求中创建另一套数据库或 Kafka 连接。

## 身份与权限

Session 保存随机 secret 的哈希及有效期。Cookie 和 Bearer 使用同一种 session token。账号停用会撤销会话，重新启用不恢复旧会话。角色只有 active 时授予权限。服务器页面与 API 分别检查权限，修改角色和用户时保留至少一名管理员。

没有默认管理员密码，也没有内置多租户产品。新业务必须在资源加载后检查归属，不能信任前端传来的 ownerId。

## 数据与文件

Drizzle schema 生成 SQL 和元数据。迁移执行检查文件完整性、已应用哈希和实际结构，并串行化同一数据库上的迁移。旧模板历史单独保留，升级使用显式增量操作。

上传先建立持久意图，再写确定对象键，最后以事务提交文件元数据、审计和事件。失败意图保留给协调清理，删除前核对引用。已提交附件不能按文件年龄直接删除。local 与 S3 都遵循同一规则。

## 后台处理

Outbox 发布至少一次。发布成功后数据库确认失败可能重发，因此消费者需要幂等。领取记录有所有者、过期时间和代次；失去租约的旧 worker 不能确认新一代任务。

消费者将幂等状态、任务、任务事件和演示 receipt 一起提交。Kafka offset 提交是后续步骤，失败不会抹掉数据库成功。演示 handler 处理 echo、文件和遥测事件，实际产品需加入自己的数据库用例或具有接收方幂等约束的外部调用。

## 验证层级

contracts 测试验证输入输出语义，数据库测试验证事务和迁移，worker 测试验证真实 PostgreSQL/Kafka 故障路径。浏览器检查表单、刷新、导航和会话。生产构建检查单独启动实际制品。CI 使用同一套命令，不以源码字符串检查代替行为验证。

## 生产评估修复后的边界

所有会提交用户输入的管理表单在交互绑定前禁用提交，并显式声明 POST。个人账号页面提供本人改密，用户管理提供其他账号重置；运维恢复命令需要目标账号、环境变量中的新密码及显式确认。密码字符不做 trim，既有长密码仍可登录；新设置密码有长度上限。每次轮换都重新验证权限或旧凭据，密码更新、会话撤销、审计和 outbox 同事务提交。

上传使用短事务建立 writing 意图与租约，再在身份锁外写对象，最后以短事务重新验证权限、租约及引用并提交。失败 PUT 的结果可能不确定，因此不自动删除 blocked 对象。确认原写入进程已停止且远端写入已结束后，运维入口才允许处置。S3 写请求不自动重试，防止成功重试掩盖仍在执行的首次写入。本地文件写入同步文件与目录；删除同步目录。不能由此推导存储硬件一定满足断电持久性。

worker 的心跳由实例专属队列顺序写入，终止状态不可被旧 running 写覆盖。运行参数传入真实消费路径，非法 Unicode 在入库前进入隔离流程。完成键可压缩但不删除身份与哈希。

历史清理默认 dry-run，要求明确保留天数和有界批量。只删除已完成任务的历史事件、已发布 outbox 和过期遥测/审计，压缩完成键与回执内容；保留用于重复检测的身份、状态和哈希。健康查询在 PostgreSQL 聚合，不把全部历史记录加载到 Web 内存。

应用备份按同一数据库快照取得已提交文件引用并复制不可变对象。恢复必须使用空数据库和空存储，完整比对引用及字节校验和后重绑已提交位置。部分失败不开放目标，不覆盖原部署。详细操作见 recovery.md。
